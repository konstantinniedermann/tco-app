# Freiwilliger Passkey (#44) — Umsetzungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mitglieder können freiwillig einen Passkey einrichten, sich damit ohne Code anmelden und ihre Passkeys im neuen Profil verwalten; der Login per Brief- und Mail-Code bleibt unverändert.

**Architecture:** Ein eigener `PasskeyDienst` neben dem bestehenden `LoginDienst` (`src/lib/server/login/`), der die Bibliothek nur über eine schmale Schnittstelle `PasskeyPruefer` anspricht (in DB-Tests ersetzbar). Anmelden mit Passkey erzeugt dieselbe Sitzung wie der Code (`erstelleSitzung`); ein Merker an der Sitzung steuert den Hinweis auf der Startseite. Oberfläche: Hinweis auf `/`, zwei Karten auf `/login`, neue Seite `/profil`, Reiter Start · Profil.

**Tech Stack:** SvelteKit 3 / Svelte 5 (SPA, `ssr = false`), Drizzle + PostgreSQL, `@simplewebauthn/server` 14.x, `@simplewebauthn/browser` 14.x, Vitest (Projekte `einheit`, `datenbank`), Playwright (Projekte `iphone` = WebKit, `android` und `desktop` = Chromium).

**Spec:** `docs/superpowers/specs/2026-11-04-passkey-design.md`

## Review Focus

1. **Wiederholte Anmelde-Antwort** (dieselbe Passkey-Antwort zweimal, Challenge schon verbraucht) → zweites Mal `falsch`, keine zweite Sitzung. Test in Task 4.
2. **Unbekannter oder abgelaufener Vorgang** (Vorgang erfunden, älter als 5 min, leer) → `falsch` (400), kein 500. Test in Task 3 (Speicher) und Task 5 (Schnittstelle).
3. **Kaputter Körper** (kein JSON, `antwort` fehlt, Zahl statt Objekt) bei allen POST-Schnittstellen → 400/415 ohne Inhalt im Log. Test in Task 5.
4. **Fremden Passkey entfernen** (ID eines anderen Kontos) → `nicht-gefunden` (404), der fremde Passkey bleibt. Test in Task 4.
5. **Dasselbe Gerät zweimal einrichten** (Kennung existiert schon, Eindeutigkeitsfehler) → `falsch`, kein 500, bestehender Eintrag unverändert. Test in Task 4.
